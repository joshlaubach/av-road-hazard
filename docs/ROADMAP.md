# Roadmap

Last updated: 2026-10-26 (finished rows moved to Done; Next renumbered). Whoever finishes or changes a row should update this file in the same PR. If a row here disagrees with the code, the code is right and this file is out of date.

The order follows the core-first gate ([ADR 0011](adr/0011-core-first-gate.md)). The core (detector, defect classifier, fusion and the synthetic fusion evaluation) has to give reportable numbers before RAG, the web UI or deployment go beyond stubs.

On nuScenes mini at score 0.5, the default MobileNet model finds 38% of pedestrians (90% range 35-42%) and 21% of cyclists (14-31%, from only 57 objects). Its CPU speed meets the p95 limit of 2 s at 24, 4 and 2 threads. |

The class names are verified against the paper and the annotation files, and pinned by a test. |
| Fusion | Done | `fusion/fuse.py` sets `in_road` and `near_objects` and computes the deterministic `hazard_score`. Severity is still "unknown" (see Next, row 2). |
| Evaluation tooling | Done | Code in `eval/`, plus notebooks `03_eval_classifier` and `04_eval_detector`. They report 90% Wilson intervals, a provenance block and a recall guard. |
| Hard-negative training | Done, repeat 10 accepted 2026-10-26 | `extra_negatives` repeated 10 times (run `tile-fold0-hn2`, 680 extra tiles) cut nuScenes alerts from 80 to 53 over 404 frames (0.198 to 0.131 per frame) and the clean probe tiles still flagged from 23 to 13 of 23. The recall guard passes: validation recall changed by -1.9 (D00), +3.3 (D10), +2.8 (D20) and +0.9 (D40) points, and 5 of the 6 reviewed cracks are still flagged. Repeat 20 failed the guard (D10 lost 6.6 points, 5 of 6 cracks). Limits: one fold, one reviewer, 5 of 6 is the lowest passing score, and 13 of the 53 alerts have not been reviewed yet. |
| Real pipeline end to end (was row 2) | Done on local images 2026-10-26 | `python -m tools.smoke_analyze` with `USE_STUBS=0` and the chosen checkpoint, on 20 local images (12 nuScenes frames, day and night, and 8 RDD2022 images from Japan, Czech, Norway and India; none are committed). All 20 gave valid records, 0 failures, and the road model loaded for every image (no unknown `in_road`). Overlays for all 20 checked by eye: detector boxes sit on the cars, trucks, buses and people, and defect boxes line up with the tile grid on the road, so no shifted coordinates. Defects were raised on 3 of 20 images. Findings: (1) one night frame has a large "car" box around headlight glare, and one Czech/India frame has a box on the car's own hood or bumper edge, so the detector gives occasional false boxes; (2) a Norwegian frame gave 15 overlapping defect boxes, because neighboring flagged tiles are not merged into one defect; (3) the app reads real environment variables only, not `.env`, so `DEFECT_CHECKPOINT` must be set in the shell. `api/pipeline.py` keeps its stub switch for tests only. Still open: the 20 license-clean fixture images for CI (see Next, row 5). |
| Synthetic fusion evaluation (was row 1) | Done 2026-10-26; the pipeline fails 1 of 4 criteria | `python -m tools.eval_fusion_synthetic` (code in `eval/fusion_synthetic.py`, settings and pass criteria in `configs/eval_fusion.yaml`). 215 RDD2022 test-split patches (never trained on) pasted onto 30 nuScenes frames with hand-outlined roads, run through the real pipeline, one patch per run. Road ground truth is the hand-drawn polygon, not the road model; a patch counts as on or off road only if it clears the polygon by 30 px. A patch is found when a reported defect box contains its center (reported boxes are 384 px tiles, so box overlap is low by design: median IoU 0.12). Results (90% ranges): on-road patches found 54 of 170 (26-38%); by width: under 64 px 3 of 57 (5%), 64-128 px 17 of 56 (30%), 128 px and up 34 of 57 (60%, range 49-70%). Off-road patches reported as defects: 0 of 45 (0-6%). `in_road` agreed with the hand-drawn road for 52 of 54 found defects (96%, range 89-99%). `near_objects` found 71% of the ground-truth nearby objects (precision 88%). On the 30 unpatched frames the pipeline raised 1 defect. Verdict: FAIL, because large patches are found 60% of the time against the 70% minimum. The criteria are provisional and were not changed after seeing the result. Limits: pasted patches are not real damage (different lighting and blur), 30 frames from one city pair, the polygons were drawn by one person, only ground-truth objects a COCO detector can name count for `near_objects`, and 55 placements found no room and were skipped. Distances are image pixels, not meters. Small defects (under 64 px wide in the frame) are almost never found, so the write-up must state that range. |
| Real-photo check on the Stellenbosch pothole photos | Done 2026-10-26 | 14 dashboard-camera photos from the CC0 Stellenbosch dataset (South Africa), run through the real pipeline at full size with the dashboard cropped off, compared with the authors' own pothole boxes. The authors marked 44 potholes; the pipeline's defect boxes (384 px tiles) covered the centers of 10 of them (23%), and raised 15 defect boxes that were not near any marked pothole (the authors may not have marked every defect, so these are not all mistakes). It does best when the damage is large in the frame: one worn street got both its marked potholes (84-100% confidence, in the road, 3 overlapping boxes), while a shallow pothole beside a manhole cover was missed and a false alarm was raised on plain road. Shrunk to 1600 px wide the pothole in that photo (about 100 px) was missed entirely, so **photos are analyzed at full size, and shrunk copies are for display only**. This agrees with the synthetic evaluation: small defects are the weak spot. Local only: `data/demo_photo/` (not committed) holds two candidate demo photos with their source record. |
| Core-first gate | Accepted 2026-10-26 | [ADR 0011](adr/0011-core-first-gate.md): RAG, the web UI and deployment stay at stub level until the core produces reportable numbers. Building `web/` against the stub API is allowed. |

## Production-ready means

- [ ] The core numbers (the synthetic evaluation above and the write-up in Next, row 3) are in the README with their limits, not only in notebooks.
- [ ] The classifier checkpoint and thresholds are chosen, and the choice is backed by a recorded guard result.
- [ ] The stubs are off by default, and `USE_STUBS` is used only in tests.
- [ ] Everything the hosted demo shows has a cleared license (RDD2022, COCO weights, road model), and nothing derived from nuScenes is shown.
- [ ] Uploaded photos are analyzed at full size; any shrinking is for display only.
- [ ] The Docker build and compose file have been run with real models, and CI is green on `main`.
- [ ] The hosted demo meets the CPU latency target, and the rate limit, request and upload limits and Claude spend cap are tested.
- [ ] The provisional values (classifier thresholds, `min_road`, detector score 0.5) are either re-measured on more data or marked provisional in the README.
